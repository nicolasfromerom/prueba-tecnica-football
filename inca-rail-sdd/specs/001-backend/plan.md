# Plan backend
Organizar app/Modules/{Auth,Users,Roles,Permissions,Competitions,Teams,Players} por Domain, Application, Infrastructure y Presentation; Shared para cliente externo y respuestas. Entidades PHP puras, repositorios por contrato, adaptadores Eloquent, controladores delgados, Form Requests y Resources. Configurar rutas sin prefijo adicional para respetar rutas exactas. Passport con emisión de token personal tras validar credenciales. Reglas RBAC verificadas en cada operación; permisos vigentes en servidor. Proteger último administrador activo.
Persistir catálogo y plantillas con identificadores externos únicos y transacciones. No confundir catálogo con importación completa: guardar marca de sincronización exitosa. Consultar endpoint externo de equipos por competición y obtener plantillas según cobertura real; no inventar camiseta ausente. Reservar cupo antes de cada llamada externa, incluso reintentos; cache compartida con lock atómico, TTL 24h configurable. Si hay copia completa devolver 200 con meta.stale; si no, 429 o 503. GET de importación exigido por enunciado; documentar efecto lateral y usar Cache-Control: no-store. El lector solo obtiene detalle local; sin copia devuelve 403. Contrato JSON: success, message, data, meta; error con code y details. Identificadores de rutas de fútbol: external_id de forma consistente. Validar decisiones y supuestos en README.

Ejecutar Composer y Artisan en el servicio backend. DB_HOST=db; CACHE_STORE=database con migraciones de caché y locks; validar atomicidad del limitador. No usar Node ni TypeScript en backend. Servidor de desarrollo en 0.0.0.0:8000; configurar CORS si se accede directamente desde el navegador.
