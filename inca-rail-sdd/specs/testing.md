# Plan maestro de pruebas
Ejecutar primero [entorno Docker](000-development/testing/README.md), luego [backend](001-backend/testing/README.md), [frontend](002-frontend/testing/README.md) y [entrega](003-delivery/testing/README.md). Usar base de datos de prueba, usuarios admin/consulta, token externo propio y datos controlados. Para fallos y concurrencia usar respuestas simuladas en entorno de prueba, nunca agotar deliberadamente el proveedor. Registrar por escenario fecha, resultado PASS/FAIL/BLOCKED, evidencia y commit; no incluir secretos. Todos comienzan PENDING. Repetir escenarios afectados por correcciones.
